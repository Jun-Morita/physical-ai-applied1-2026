# 収録前のコード点検（2026-10-03）

実データ取得前に、収録・学習・評価の共通処理を整理した。今回の作業ではFlightGearの起動や飛行データの取得は行っていない。

## 修正した問題

| 問題 | 対応 |
| --- | --- |
| 動画終了時のBrokenPipeやタイムアウトでメタデータ保存まで中断する | 終了処理を分離し、終了失敗を記録して保存を継続 |
| 状態が1件もない収録を完了扱いする | 空の収録は `incomplete` にする |
| MLP学習が時刻の巻き戻りや範囲外操作を十分に検査しない | MLP/VLA共通の受付検査で拒否する |
| 受信時刻・画像ファイル名を変えたコピーが重複検査をすり抜ける | 状態と画像内容・シミュレーション時刻から重複を判定 |
| 画像の前後の間にある停止を見落とす | 対応付け区間全体の停止を検査 |
| 短い診断飛行を学習・成績比較に混ぜられる | `--purpose diagnostic` を追加し、両方から除外 |
| 不正な時刻やJSON値を保存できる | 非有限値を拒否し、JSONの置換前に検証 |
| モデルハッシュ計算時に重み全体をメモリへ読む | ストリームによるハッシュ計算に変更 |

画像の次の状態の探索は二分探索へ変更した。データ受付は `landing/data.py`、保存は `landing/storage.py`、録画終了は `landing/recording.py` に集約し、既存の公開インポートは維持している。Pythonコードの未使用インポートと書式も整理した。

## 検証結果と限界

- unittest：20件合格。収録、通信異常、データ検査、飛行単位の分割、比較条件、録画終了の回帰テストを含む。
- Ruff 0.15.7：静的チェックと書式チェックに合格。
- RTX 3060：実際のSmolVLA重みで、合成入力の追加学習1ステップ・検証・保存・再読込・再推論が成功。PyTorchの最大確保メモリは約2.08 GB。作成したモデルは一時ディレクトリとともに削除した。

合成入力の診断は、データ読み込みを模擬した接続確認であり、人の操縦データによる学習ではない。既存の実FlightGear接続確認は [VLA手順書](vla-pipeline.md) に記録している。動作中の画像と状態の時刻差、F310の割当、各機体の進入設定、接地信号、着陸性能は実機での確認が残る。
