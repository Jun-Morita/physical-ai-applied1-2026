# 機体選定：再現度を優先

調査日：2026-09-27。Ubuntu・RTX 3060・Python/uvでの模倣学習と、羽田での着陸が前提。

## 選定結果

戦闘機は **F-14B（Zaretto系FlightGearモデル）**、旅客機は **Boeing 747-400 / GE CF6-80C2B1F（FlightGearモデル）** を使用する。2026-09-27にユーザーが747とF-14の採用を決定した。
機体名の知名度より、飛行特性の出典・着陸関連の実装・制約を追えることを重視した資料ベースの選定。選定時点では手元での動作・性能は未検証。その後の導入確認は [検証記録](simulator-validation.md) を参照。
実機との定量誤差を比較する共通ベンチマークは確認できておらず、全候補中で最も正確と断定するものではない。

## 戦闘機：F-14B

[開発者の説明](https://zaretto.com/content/realistic-grumman-f-14-simulator-flightgear)と[開発リポジトリ](https://github.com/Zaretto/fg-aircraft)を参照。

- F-14A/Bを扱うJSBSimモデル。開発者は風洞試験データに基づく空力モデルと説明し、AFWAL-TR-80-3141などを明記している。
- 可変後退翼、脚・フラップの空力影響、油圧・電気系統も扱う。F110エンジンはNASA資料を参照している。
- 重要な限界：開発者が精度を述べる範囲は低速・クリーン形態。高速域やフラップ等は別資料からのモデル化で、実機と完全には一致しないと明記している。着陸形態の高精度を保証したと解釈しない。
- 初期選定はB型。A型のTF30圧縮機失速などの故障再現を主題にせず、通常着陸の学習から進める設計判断。
- 開発者ページにはGPL v3と記載。導入する版と各同梱素材の表示を確認する。

F/A-18Fは[作者の公開投稿](https://forum.flightgear.org/viewtopic.php?p=424422)で飛行モデルが基本的なものとされており、再現度優先の初期選定から外す。F-15C/Dは[空力資料の出典](https://zaretto.com/content/flight-simulation-aerodynamic-data-aerodata-downloads)を追える比較候補として残す。

## 旅客機：Boeing 747-400

[確認したモデルファイル](https://github.com/LincolnWorks-FlightGear/747-400/blob/master/747-400.xml)と[機体パッケージ](https://github.com/LincolnWorks-FlightGear/747-400)を参照。

- 型式とエンジンが747-400 / GE CF6-80C2B1Fと明記されている。
- FCOM、Flight Planning and Performance Manual、整備資料、大型ジェット機の数理モデル資料などを参照文献として列挙している。引用元資料の全内容と実装の一致は未照合。
- 重量・慣性・搭載位置、前脚と4つの主脚接地点、摩擦・ばね・減衰・ブレーキの定義を確認した。
- 重要な限界：一部重心・配置の値に推定との注記がある。古い大型ジェット資料も参照されており、すべてが747-400の実測値ではない。release=PRODUCTIONという表記も第三者の精度認証ではない。
- 機体パッケージには外観、パネル、Systems、Nasalがある。飛行モデルXMLだけ取り出して同じ機体挙動になるとは仮定しない。
- パッケージのCOPYINGはGPL-2.0。導入版と素材別表示を記録する。

JSBSim標準737より参照資料と対象型式が具体的な点を評価した。A320-familyも比較したが、[開発元](https://github.com/legoboyvdlp/A320-family)は主要開発の保留を明記し、FlightGear側のシステム連携も多いため今回は優先しない。これはA320の精度が低いと判断したものではない。

## 導入時に確かめること

1. 正式配布版・開発版の関係と対応FlightGear版を確認し、使う機体パッケージのコミットまたは配布版を固定する。
2. 同じ重量・重心・脚・フラップ条件で、参照資料から取得できる進入速度・トリム・推力などと比較する。
3. 接地位置、脚の沈み込み、跳ね返り、ブレーキによる減速を確認する。見た目と物理座標も照合する。
4. 操縦入力から舵面までの制御系を保持する。手動・AIで同じ入力経路を使う。
5. 自動操縦・自動推力と安定増強装置を区別し、どの補助が有効だったかをログに残す。
6. JSBSim単体への切り出しで機体システムが失われる場合は、FlightGear内蔵JSBSimを動かしてPythonから入出力する構成を検討する。
7. 学習・手動収録・評価で同じ物理モデルと設定を使用する。状態リセットと時刻同期を検証する。

2026-09-28に両機を取得し、FlightGear内で飛行モデルを読み込めることを確認した。操縦・性能測定は未実施。互換性修正と制約は [検証記録](simulator-validation.md) を参照。
